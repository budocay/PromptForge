# SPEC F-033 — Écoute réseau limitée à la boucle locale par défaut

Statut : brouillon
Tier : standard
Revue : reviewer-frontend

- Objectif (une phrase, côté métier) : les prompts restent sur la machine de l'utilisateur, y compris sur un réseau partagé (bureau, coworking, Wi-Fi public), tant qu'il n'a pas choisi d'ouvrir l'accès.
- Constat de départ : `launch_web()` écoute sur `0.0.0.0` par défaut (`promptforge/web/interface.py`, aussi via `python -m promptforge.web.interface`), et le lanceur démarre Ollama sous Windows avec `OLLAMA_HOST=0.0.0.0:11434` (`launcher.py`), ce qui expose l'interface et l'API Ollama, sans authentification, à tout le réseau local. La CLI et `start.py` utilisent déjà `127.0.0.1`, et les compose publient déjà sur `127.0.0.1` (D-036).
- Critères d'acceptation :
  - F-033-AC1 : QUAND `launch_web()` est appelé sans argument `host`, LE SYSTÈME DOIT écouter sur `127.0.0.1`.
  - F-033-AC2 : QUAND le lanceur démarre Ollama sous Windows et que `OLLAMA_HOST` n'est pas défini dans l'environnement, LE SYSTÈME DOIT le démarrer avec `OLLAMA_HOST=127.0.0.1:11434`.
  - F-033-AC3 : SI `OLLAMA_HOST` est déjà défini par l'utilisateur, ALORS LE SYSTÈME DOIT conserver sa valeur.
  - F-033-AC4 : SI l'interface web est lancée sur une adresse autre que la boucle locale, ALORS LE SYSTÈME DOIT journaliser un avertissement indiquant qu'elle est joignable depuis le réseau sans authentification.
- Hors périmètre (explicitement) : authentification de l'interface ; images et compose Docker (déjà restreints) ; cible `make web-public`, qui est un choix explicite.
- Pourquoi ce tier : comportement modifié dans des modules existants, sans nouveau module ni dépendance.
- Agents : agent-frontend
- Dépend de : rien
